# Проверка кандидата 1.0.0

Дата: 7 сентября 2026. Живое подключение проверено на Apple Silicon.
Собраны отдельные DMG/ZIP для arm64 и x64. Это кандидат для ручной установки:
публичный стабильный выпуск ещё требует перечисленных ниже проверок и подписи Apple.

## Автоматические проверки

- `npm run lint`: успешно (`tsc --noEmit`).
- `npm run build`: успешно, включая Swift и native self-tests.
- `npm test`: 36 тестов в 12 файлах, успешно. Компиляция AppleScript проверяет
  настоящий текст запуска администратора, но не исполняет его.
- Native helper для x64 скомпилирован отдельно; self-tests выполнены через Rosetta.
- `npm audit` и `npm audit --omit=dev`: 0 известных уязвимостей на дату проверки.
- Xray принимает конфигурации маршрутизации, PF — синтаксис сгенерированных правил.
- Профили VLESS, Trojan и Hysteria2 проходят нативную валидацию с DoH и без него.
  Файловые пути и HTTPS-адреса вне настроек DNS отклоняются.
- Проверены обработка ошибок обновления, включение защиты в активном сеансе,
  исключение старых артефактов из манифеста и отказ при неполной паре DMG/ZIP.
- Workflow GitHub Actions разбирается как YAML и содержит сборку двух архитектур.
  Исполнение на GitHub пока не проверено; отдельный репозиторий не опубликован.

## Живое подключение

В полном прогоне прошли 20 из 21 проверки. Единственная неуспешная проверка —
первичный подсчёт DNS/DoT-пакетов (1). Затем DNS-блокировка была перемещена перед
разрешением сокетов ядра, а подсчёт стал учитывать только строки пакетов tcpdump.
Целевой повторный прогон прошёл 8 из 8 проверок, физические DNS/DoT-пакеты: **0**.
Это полный исходный прогон плюс повторная проверка исправления, а не новый полный
прогон финальной сборки. Исходные результаты сохранены без исправления задним числом:

- [Полный исходный прогон](qa/acceptance-initial.json).
- [Повторная проверка DNS и соединения](qa/acceptance-dns-retest.json).

Подтверждено:

- HTTPS через туннель по IPv4 с изменением внешнего IP; доступность HTTPS по IPv6.
- UDP DNS через туннель; блокировка запросов к физическому DNS-резолверу роутера.
- Отсутствие исходящих пакетов на портах 53/853 активного физического интерфейса
  в окне повторного захвата. Это ограниченный тест, не доказательство отсутствия
  утечек на всех интерфейсах и при любых переходных состояниях.
- Включение Kill Switch во время соединения и сохранение HTTPS внутри туннеля.
- Блокировка прямого физического HTTPS, IPv4/IPv6 после SIGKILL собственного ядра.
- Автоматическое переподключение после SIGKILL; счётчики трафика не уменьшаются.
- Маршрутизация `/usr/bin/curl` в режимах исключения и включения; контрольный
  запрос в режимах `bypassRu` и `blockedOnly` получает ожидаемый выходной IP.
- Намеренное отключение восстанавливает прямой доступ; корневые правила PF
  сохраняют исходный хеш. Настройки и подключение восстановлены в конце тестов.

## Интерфейс и упаковка

- Размеры окна 460×800 и 400×620, страницы и темы проверены с тестовыми данными.
- Установленное приложение запускается; вход через браузер, аккаунт, подписки
  и серверы загружаются. Выход через ⌘Q работает. Пользователь подтвердил интернет
  через Levik с отключённым вторым VPN.
- Проверены вложенные подписи обоих пакетов командой `codesign --verify --deep --strict`.
- Оба DMG прошли `hdiutil verify`; все четыре DMG/ZIP прошли проверку SHA-256.
- Сформирован общий `latest-mac.yml` и `SHA256SUMS.txt` для четырёх артефактов.
- Intel helper прошёл self-tests, Intel Xray 26.7.28 запустился через Rosetta;
  это не установка на физическом Intel Mac.
- Подпись ad-hoc. На Mac нет Developer ID; нотариализация и подписанное OTA не выполнены.
